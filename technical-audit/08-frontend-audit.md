# 08. تدقيق الواجهة الأمامية

## البنية

| الجانب | التنفيذ |
|---|---|
| النمط | SPA بلا إطار عمل ولا خطوة بناء |
| الحالة | كائن عام `UA.S` مع وحدات تضيف نفسها إليه |
| الرسم | `UA.render()` يبني HTML نصيًا ويستخدم `innerHTML` |
| التوجيه | `UA.go(view)` مع `UA.views` و`UA.loaders`، دون روابط URL لكل شاشة |
| الأحداث | تفويض عبر `data-act` مع 84 مستمعًا على `document` |
| البيانات | `api()` في `app.js`، و18 استدعاء `fetch` مباشرًا |
| النماذج | حقول HTML يدوية، و`UA.formKit` لجزء منها، وتنسيق CSS موحد لبقية النوافذ |
| التحقق | في الخادم أساسًا، ومع بعض التحقق في الواجهة |
| التفويض | `view_gate.js` يخفي الشاشات والتبويبات، والخادم هو الحامي الفعلي |
| التحميل الكسول | 12 شاشة عبر `LAZY` في `app.js:624`: المالية والمشتريات والحسابات والإرشادات وشاشات v12 |

## مشكلات مؤكدة

### FE-01: النقر داخل نوافذ المالية والمشتريات يغلقها. عالية.

- **الموقع:** `public/finance.js:695`، `public/procurement.js:592`.
- **السبب:** `onclick="event.stopPropagation()"` معالج مضمن تمنعه سياسة CSP `script-src 'self'`، فيصل النقر إلى الخلفية التي تحمل `data-act` الإغلاق.
- **الدليل:** جُرّب محليًا في شاشتي المشتريات والمالية: فُتحت النافذة، وبعد نقرة داخلها أُغلقت، مع رسالة انتهاك CSP في وحدة التحكم.
- **الأثر:** يفقد المستخدم ما كتبه في النموذج.
- **التحقق:** افتح «مورد جديد» وانقر داخل النافذة.

### FE-02: أزرار الطباعة في 6 مواضع لا تعمل. متوسطة.

- **الموقع:** `corr.js:200`، `finance.js:467` و878، `payroll.js:475` و1243، `procurement.js:880`.
- **السبب:** `onclick="window.print()"` ممنوع بالسياسة نفسها.
- **الدليل:** جُرّب زر طباعة تقرير المالية محليًا: لم تُستدعَ `window.print` وظهرت رسالة CSP.

### FE-03: `/api/services` يُحمَّل لكل مستخدم عند البدء. متوسطة.

95 إلى 118 كيلوبايت عند كل دخول، حتى لمن لن يقدم طلبًا. يمكن تأجيله إلى فتح نموذج الطلب.

### FE-04: تحميل 55 سكربتًا فورًا. متوسطة.

الوحدات الكبيرة مثل `payroll.js` و`enterprise_suite.js` و`student_affairs_suite.js` تُحمَّل للجميع. والطالب يحمّل شاشات الموظفين كاملة، وهذا يكشف بنيتها أيضًا. ومع `no-cache` لا يُستفاد من أرقام الإصدار `?v=` للتخزين الطويل.

### FE-05: طبقات تعديل بعد الرسم. متوسطة.

11 `MutationObserver`، منها مراقبة `document.documentElement` أو `document.body` كاملين في `ux_restructure.js:662` و`tablefilter.js:146` و`select_combo.js:133` و`ux_polish.js:258` و`ux_flow.js:329` و`i18n.js:511`. كل تغيير في الصفحة قد يوقظ عدة طبقات، وكل `UA.render` يعيد بناء المحتوى، فتتكرر الدورة.

### FE-06: جداول كبيرة دون ترقيم افتراضي في الواجهة. متوسطة.

شاشة التدقيق ترسم 500 صف دفعة واحدة، ولا يوجد عرض افتراضي للصفوف الظاهرة.

## مشكلات أمنية في الواجهة

| البند | التقييم |
|---|---|
| تخزين الرمز | `sessionStorage['uni_sid']`، `app.js:59`. انظر SEC-09 |
| XSS | لا يوجد معقّم مركزي، والحماية هي `esc()` يدويًا في 119 موضع `innerHTML`. لم يكشف الفحص الجزئي استغلالًا، لكن لم تُراجع كلها. CSP يحد الأثر بقوة |
| `public/archify` | له CSP أضعف فيه `unsafe-inline`، `http.js:174-178` |
| بيانات حساسة في المتصفح | `sw.js` لا يخزن `/api/`، وهذا صحيح. لكن `ux_card.js:29` يكتب سجلات البطاقة في `localStorage`، ويجب مراجعة محتواها |
| التفويض في الواجهة | لم يُعامَل كبديل عن الخادم: مسارات الخادم تفحص بنفسها |

## أمور جيدة

- `sw.js` يستبعد `/api/` من التخزين.
- التحميل الكسول لـ`i18n_en.js` و12 شاشة.
- اختبار `front_scripts_load.test.js` يتأكد أن كل سكربت يتحمل دون خطأ.

## ما لم يُفحص

تسرب الذاكرة عبر جلسة طويلة، والأداء على هاتف فعلي أو شبكة بطيئة، وعمليات إعادة الرسم بالتفصيل. ويلزم لذلك Chrome Performance وMemory على بيانات حقيقية.

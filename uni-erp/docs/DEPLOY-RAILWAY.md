# النشر على Railway (نسخة تجريبية)

> للتجربة والعرض فقط وببيانات وهمية. لا تُدخل بيانات طلاب حقيقية على استضافة تجارية قبل موافقة الجامعة.
> أسماء الأزرار في Railway وGitHub قد تتغير قليلاً مع الوقت؛ المعنى واحد.

## ما الذي أُعدّ في المشروع
- `railway.json` و`Dockerfile.railway`: يبنيان النظام على Railway (Railway يرفض تعليمة `VOLUME` الموجودة في `Dockerfile` العادي، لذلك أُنشئ ملف مستقل).
- `scripts/start-cloud.js`: عند أول تشغيل (قاعدة فارغة) ينشئ الحسابين `admin` (مدير النظام) و`auditor1` (مدقق) بقيمة المتغير `SEED_PASSWORD`. **إن لم يُضبط تُولَّد كلمة عشوائية تظهر مرة واحدة في Deploy Logs وتُغيَّر عند أول دخول؛ ويُفضَّل ضبط `SEED_PASSWORD` قوية في متغيرات Railway قبل أول نشر.** لقاعدة قائمة: `npm run accounts` يعيد ضبط الحسابين ويفك قفلهما دون المساس بغيرهما.
- `GET /api/health`: مسار فحص الصحة الذي يستخدمه Railway.
- `COOKIE_SECURE=1` و`TRUST_PROXY=1` مضبوطان داخل الصورة، وHTTPS تتولاه Railway.

## الخطوات
1. **GitHub:** أنشئ حساباً مجانياً، ثم New repository باسم مثل `uni-erp` (اجعله **Private**). اضغط «uploading an existing file» واسحب **محتويات** مجلد `uni-erp` (وليس المجلد نفسه) بحيث يظهر `package.json` في الجذر، ثم Commit.
2. **Railway:** سجّل الدخول بحساب GitHub، ثم New Project ← Deploy from GitHub repo ← اختر المستودع. سيقرأ `railway.json` ويبني تلقائياً.
3. **القرص الدائم (إلزامي):** افتح الخدمة ← Volumes (أو Add Volume) ← **Mount path: `/app/data`**. بدونه تضيع الحسابات والطلبات مع كل تحديث. ملفات الاختبارات والتكليفات (`uploads/lms_assignments`) محفوظة على هذا القرص لكنها **خارج النسخة الاحتياطية اليومية**، فلأنها تكبر مع كل تسليم يجب تفعيل نسخ القرص من الاستضافة أو نسخها دورياً.
4. **النطاق:** الخدمة ← Settings ← Networking ← Generate Domain. ستحصل على عنوان مثل `https://xxxx.up.railway.app`.
5. **المتغيرات:** الخدمة ← Variables، أضف:
   - `PUBLIC_URL` = عنوان النطاق الذي حصلت عليه (يُستخدم في رموز QR للتحقق من الوثائق)
   - `UNIVERSITY_NAME` = اسم الجامعة
   ثم أعد النشر (Redeploy).
6. **الدخول:** `admin` وقيمة `SEED_PASSWORD` (أو الكلمة العشوائية من Deploy Logs). من «الحسابات والصلاحيات» أنشئ بقية الحسابات الإدارية.
7. ادخل بـ `admin` وسجّل طالباً تجريبياً (يُولَّد له اسم مستخدم مثل `CCS-2026-0001`) وجرّب بوابته.

## على الهاتف
بعد النشر على HTTPS يظهر خيار تثبيت التطبيق كاملاً (وعامل الخدمة يعمل). لبناء APK: اذهب إلى pwabuilder.com، أدخل عنوان نظامك، واختر Android.

## إذا ظهرت مشكلة
- **فشل البناء بسبب VOLUME:** تأكد أن `railway.json` و`Dockerfile.railway` في جذر المستودع.
- **EACCES / permission denied عند الكتابة:** أضف متغير `RAILWAY_RUN_UID` بقيمة `0` وأعد النشر.
- **ضاعت كلمات المرور:** للنسخة التجريبية فقط: احذف القرص (Volume) وأنشئه من جديد ثم أعد النشر، فتُنشأ حسابات جديدة (وتُمسح البيانات).
- **النسخ الاحتياطي:** مفتاح التوقيع `data/secret.key` وقاعدة البيانات على القرص نفسه؛ فقدانهما يعني عدم التحقق من الوثائق القديمة.

## لا أستطيع الدخول بـ admin (قاعدة قديمة أو حساب مقفل)
التهيئة تعمل على قاعدة فارغة فقط، فإن كان `admin` موجوداً من نشر سابق بكلمة مرور أخرى فلن تتغير تلقائياً. والحساب يُقفل 15 دقيقة بعد 5 محاولات فاشلة.
1. في Railway ← Variables أضف `RESET_ACCOUNTS` = `1` (ويمكن إضافة `SEED_PASSWORD` بكلمة مرور أقوى).
2. أعد النشر (Redeploy). سيُعاد ضبط `admin` و`auditor1` وفك قفلهما، ويظهر ذلك في Deploy Logs.
3. ادخل، ثم **احذف المتغير `RESET_ACCOUNTS`** كي لا تُعاد كلمة المرور في كل نشر.
محلياً: `npm run accounts`.

### إن بقي الدخول مرفوضاً بعد إعادة الضبط
- في Deploy Logs ابحث عن `[login] رفض`: يذكر السبب (لا يوجد مستخدم بهذا الاسم / الحساب معطّل / كلمة المرور لا تطابق).
- سطر إعادة الضبط يطبع كلمة المرور بين علامتي اقتباس وعدد أحرفها، فتظهر أي مسافة خفية.
- تأكد أن لوحة المفاتيح بالإنكليزية عند كتابة كلمة المرور.
- اسم المستخدم لا يتأثر بحالة الأحرف (`Admin` = `admin`).

## خطأ `Cannot find package 'pg'` عند الإقلاع
السبب: بناء Docker لم يُنفّذ `npm install`، و`pg` (عميل PostgreSQL) هو اعتمادية النظام الوحيدة.
الحل: استعمل `Dockerfile.railway` الموجود في جذر المستودع (أو في `uni-erp/` إن كان جذر النشر هو `uni-erp`)؛ كلاهما ينفّذ `npm install --omit=dev` ويثبّت أيضاً `postgresql-client` اللازم للنسخ الاحتياطي (pg_dump/pg_restore).
إذا كنت تنشر بدون Dockerfile (Railpack/Nixpacks)، فتأكد أن خطوة التثبيت تعمل وأن أمر البدء `node scripts/start-cloud.js`.


## خطأ `EACCES: permission denied, open '/app/data/secret.key'`
السبب: Railway يركّب القرص الدائم على `/app/data` بملكية root بينما يعمل التطبيق بالمستخدم `node`، فلا يستطيع قراءة `secret.key` (أو كتابته) الذي أُنشئ سابقاً بملكية root.
الحل: صار `docker-entrypoint.sh` يبدأ كـ root فيصلح ملكية `/app/data` و`uploads` و`logs` و`backups` ثم يُسقط الصلاحيات إلى `node` عبر `su-exec`. لا تضف `USER node` في Dockerfile ولا تُعطِّل الـ ENTRYPOINT.
